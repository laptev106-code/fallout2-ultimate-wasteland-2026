## 1. Архитектурный принцип: Двухуровневая речевая модель (Two-Tier Model)

Чтобы мир игры звучал живо и аутентично, реплики рядовых обывателей (`float_msg`) разделены на два строгих слоя:

```
                    [ Клик по жителю (talk_proc) ]
                                   │
                                   ▼
                   [ Проверка локации: cur_town ]
                                   │
                 ┌─────────────────┴─────────────────┐
                 ▼                                   ▼
     [ 50% Шанс: Слой 1 ]                [ 50% Шанс: Слой 2 ]
      ФОНОВЫЙ SMALL TALK               КВЕСТОВАЯ РЕАКТИВНОСТЬ
  (Погода, мозоли, цены,             (Чтение GVAR текущего города)
   быт, личные невзгоды)                             │
                                  ┌──────────────────┴──────────────────┐
                                  ▼                                     ▼
                          [ Квест НЕ РЕШЕН ]                     [ Квест РЕШЕН ]
                           Жалобы на проблему,                    Реакция на исход
                           страхи, сплетни                        (успех или крах)
```

### Слой 1: Фоновый Small Talk (Статический быт)
- Отражает постоянный фон выживания: скрип пыли на зубах, протертые сапоги, вонь кожевенной мастерской, разбавленное пиво, страх перед пустыней.
- Не зависит от действий игрока и формирует постоянную плотную атмосферу города.

### Слой 2: Квестовая реактивность (Динамика состояний мира)
- Напрямую привязана к переменным движка (`global_var(GVAR_...)`).
- До завершения квеста жители нагнетают обстановку: обсуждают пропажу людей, утечки радиации, набеги рейдеров, эпидемию наркотиков.
- После завершения квеста реплики меняются: жители обсуждают последствия, благодарят Избранного или содрогаются от жестокости произошедшего.

## 2. Железное правило изоляции (Strict City Scoping & Anti-Leak Rule)

> [!CAUTION]
> **ЗАПРЕТ ПЕРЕКРЕСТНОГО ЗАГРЯЗНЕНИЯ:** Категорически запрещено считывать или комментировать квесты чужого города.
> Гуль в реакторе Гекко **НИКОГДА** не должен говорить про крыс в Траппертауне или мафиози Нью-Рино.

### Механизм защиты в коде sFall:
1. **Первичный шлюз:** Проверка кода города `cur_town` через константы `headers/maps.h` (`AREA_KLAMATH`, `AREA_GECKO`, `AREA_REDDING` и т.д.).
2. **Внутренний изолированный блок:** Внутри каждой ветки `if (t == AREA_X)` считываются **только те GVAR**, которые принадлежат данному городу.
3. **Безопасный Fallback:** Если ни один квест города не продвинулся или значение GVAR неопределенно, движок автоматически переключается на Слой 1 (чистый локальный Small Talk).

## 3. Матрица состояний квестов (Quest State Machine)

Каждый квест имеет три фазы звучания:

| Состояние | Код в логике | Что говорят жители | Пример (Гекко, Реактор №5) |
|---|---|---|---|
| **0. Active / Unsolved** | До решения | Страх, жалобы, нарастающая катастрофа | *«В третьем контуре свистит пар! Если реактор рванет, от нас и пепла не останется!»* |
| **1. Resolved (Good)** | Успех / Мир | Облегчение, надежда, экономический подъем | *«Реактор урчит как довольный кот. Чужак из Убежища спас наши шкуры.»* |
| **2. Resolved (Bad)** | Провал / Резня | Ужас, запустение, траур, гнев | *«Они перебили инженеров станции... Скоро мы все сгнием в темноте.»* |

## 6. Фактическая архитектура маршрутизации в `gl_wv_core.ssl`

```c
procedure get_town_line_id begin
   variable line;
   // 1. Приоритетный рубеж: Реакция на игрока (Броня, Пушки, Монстры в отряде, IQ < 4)
   line := get_player_react_line;
   if (line > 0) then return line;

   // 2. Второй рубеж: 50% Квестовые сплетни текущего города
   if (random(1, 100) <= 50) then begin
      line := get_quest_line;
      if (line > 0) then return line;
   end

   // 3. Базовый рубеж: Фоновый локальный Small Talk
   return get_small_talk_line;
end
```
